Anonymous is a TryHackMe machine with an FTP server open to anyone. Inside it I found a cleanup script that ran on a timer and that anyone could edit, so I replaced it with a reverse shell and got in as namelessone. For root, I found env with the SUID bit set and used it to start a root shell.

#Q1–Q3. Open ports, and the services on 21 and 139/445

1Scan all ports

-p- scans all 65535 ports, not just the common 1000. The scripts already show that anonymous FTP login is allowed and that the scripts folder is writable. That is a strong early hint.

This one scan answers the first three questions: 4 open ports, port 21 runs ftp (vsftpd), and 139/445 run Samba. nmap labels them netbios-ssn, but the room wants the protocol name: smb.

A hint that I am in the right place.

4Read clean.sh and its permissions

On the server, clean.sh has permissions -rwxr-xrwx. The last rwx means anyone can write to it, not only the owner. So I can change what it does.

5Notice the log keeps growing

removed_files.log keeps growing and its timestamp keeps updating, so something runs clean.sh again and again: a cron job I cannot see.

Why it works

A cron job is a task Linux runs on a timer with no person involved. clean.sh is run automatically as another user, and anyone can write to it. Whatever I put in the file runs as that user. That is the whole bug.

6Check the pics share (dead end)

They are just pictures of dogs. The real path is the FTP script, so I go back to clean.sh.

7Put a reverse shell in clean.sh

I take a Bash reverse shell from revshells.com. The IP must be my tun0 VPN IP (192.168.137.189), not my LAN IP, or the target cannot reach me.

I keep the first line #!/bin/bash and the original structure, and put the payload in the then branch:

Why it works

The script checks if [ $tmp_files=0 ] with no spaces around =. bash does not compare two values; it sees one word, 0=0, and [ word ] only asks "is this word non-empty?". It always is, so the then branch always runs. That is why the payload goes there. The #!/bin/bash line matters too: the /dev/tcp trick is bash-only and fails under plain sh.

9Catch the shell and read user.txt

When the timer runs clean.sh, a shell drops in as namelessone. The "no job control" message is normal for a raw reverse shell.

Why it works

A reverse shell makes the target connect out to me. A bind shell would open a new port on the target and wait, which a firewall often blocks. On a VPN lab like this, reverse is the safe choice.

2Find SUID binaries

A SUID file runs with its owner's rights, so a SUID file owned by root runs as root. /usr/bin/env is not normally SUID. That is my way up.
