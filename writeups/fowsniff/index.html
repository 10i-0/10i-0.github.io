Fowsniff Corp got breached and the attacker dumped staff email passwords online. I follow the breach notice to a public MD5 dump, crack it, log in to the POP3 mail server as seina, and read an email with a temporary SSH password. The user who never changed it lets me in. For root, a login-banner script runs as root on every SSH login, and my user's group can edit it.

#Q1. What ports are open?

1Scan the target

Four ports are open. Two of them are mail services (POP3 and IMAP), which is unusual for a web box and worth remembering.

#Q2–Q3. Look around, then search for public information

1Open the website on port 80

The page says employee usernames and passwords were leaked, and that the attackers hijacked the company's X (Twitter) account @fowsniffcorp. That handle is my lead.

2Search the handle

The X profile links a paste, and the GitHub repo berzerk0/Fowsniff holds the actual password dump.

#Q4. Can you decode these MD5 hashes?

1Open the leak

2Crack the hashes

I paste the hashes into Hashes.com. They are plain unsalted MD5, so they are already in its database.

Only stone's hash stays uncracked, and I do not need it.

Why it works

MD5 is fast and has no salt here, so the same password always gives the same hash. Weak passwords like these are already in public lookup tables, and "cracking" is just a lookup.

#Q11–Q12. Put a reverse shell in the banner script, and get root

1Start a listener

2Add a Python reverse shell to cube.sh

The way I pasted it replaced the banner art. That does not break anything; the banner just stops printing.

3Log in again to fire it

Why it works

On every SSH login, the system runs the MOTD (message of the day) scripts as root to build the banner, and this one calls cube.sh. Because the users group can edit cube.sh, any staff member can make root run their code at the next login.
