Easy Peasy is a Linux room full of small clues. I enumerate two web servers, read hidden page source, decode Base64 and Base62, crack a GOST hash with the room's wordlist, and use it as the Steghide passphrase to pull SSH credentials out of an image. For root, a cron script in /var/www runs as root but is owned by my user, so I turn it into a reverse shell.

#Q1–Q3. Open ports, nginx version, and the highest port

1Scan all ports

Three ports are open. Nginx 1.16.1 is on 80, SSH is on the non-default port 6498, and the highest port, 65524, runs Apache. That one scan answers the first three questions.

#Flag 1

1Brute-force directories on port 80

2Brute-force again inside /hidden/

3Read the page source of /hidden/whatever/

The page looks like a plain background image, so I open DevTools instead of assuming there is nothing there.

The paragraph is hidden with CSS, but its text is still in the source.

4Decode the Base64

#Flag 2

1Read robots.txt on port 65524

I open http://easypeasy.thm:65524/robots.txt.

The custom User-Agent value a18672860d0510e5ab6699730763b250 is 32 hex characters, the shape of an MD5 hash.

2Look the hash up

I paste it into Hashes.com, which has it in its database.

#Flag 3

1Read the Apache default page on port 65524

The Apache default page looks normal, but I read the configuration overview line by line.

Flag 3 sits in the middle of the normal Apache text, where it is easy to scroll past.

#The hidden directory

1Read the page source on port 65524

In DevTools, the same page has another hidden paragraph: "its encoded with ba...." followed by a string.

2Decode it in CyberChef

Base64 gives garbage, so I try the other bases. From Base62 gives a clean path.

The hidden directory is /n0th1ng3ls3m4tt3r.

#Crack the hash

1Collect the files from the hidden directory

http://easypeasy.thm:65524/n0th1ng3ls3m4tt3r/ shows an image of binary code, and its source holds a long hash. I save the image, the hash (in hash.txt) and the wordlist from the room.

2Crack it with john and the room's wordlist

The hash is 940d71e8655ac41efb5f8ab850668505b86dd64186a66e57d1483e7f5fe6fd81. --format=gost tells john the hash type, so it does not waste time guessing. The cracked password is the passphrase for the image in the next step.

#The SSH password

1Extract the hidden file from the image

Steghide asks for a passphrase, and the password from john works. The file holds a username, boring, and a password written as groups of 8 binary digits.

Why it works

Steganography hides data inside an ordinary file. The picture looks normal, but Steghide stored an encrypted file in it, and only the right passphrase gets it out.

2Turn the binary into text

In CyberChef I use From Binary with delimiter Space and byte length 8, so each group of eight bits becomes one character.

#User flag

1SSH in on port 6498

SSH is on 6498, not 22, so I set the port with -p.

2Read user.txt

The value has the shape of a flag, but the letters are shifted.

3Decode ROT13

The hint says "rotated", so I paste it into Cryptii with ROT13.

ROT13 moves every letter 13 places. It is a letter swap, not encryption, so it needs no key.

#Root flag

1Find a writable script in /var/www

The hidden file .mysecretcronjob.sh belongs to boring, so I can edit it.

2Read the script

shell — boring@kral4-PC
boring@kral4-PC:/var/www$ nano .mysecretcronjob.sh

The comment says it runs as root. A script I can edit that runs as root on a timer is the way up.

3Put a reverse shell in it

I take the Bash reverse shell from GTFOBins and change the address to my tun0 VPN IP and port 12345.

4Catch the root shell

Why it works

cron runs .mysecretcronjob.sh as root, but the file is owned by boring. Whatever I write in it runs as root on the next run, so the reverse shell opens with root rights.

5Read the hidden root flag

The flag file starts with a dot, so a plain ls would not show it.
